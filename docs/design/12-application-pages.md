# Application And Tool Pages

Ferramentas internas, planners, trackers, dashboards e aplicações web não precisam utilizar a estrutura completa de uma landing page.

Devem preservar:

- tokens;
- tipografia;
- componentes;
- cores;
- acessibilidade;
- responsividade;
- linguagem visual.

Podem omitir:

- hero comercial;
- pricing;
- prova social;
- CTA de venda;
- footer institucional completo;
- navegação comercial.

A função da ferramenta sempre prevalece sobre a estrutura comercial.

## Regras Complementares

- usar densidade maior apenas quando a tarefa exigir;
- preferir Montserrat em superfícies operacionais;
- reservar PT Serif para títulos de página ou momentos editoriais;
- manter ações principais em rosa;
- usar roxo escuro para navegação ou áreas de identidade;
- exibir estados vazios, loading, erro e sucesso;
- proteger layout contra transbordamento de tabelas, labels e botões;
- não transformar ferramenta em landing page.

## Estrutura Recomendada

- app shell ou topbar funcional;
- título de contexto;
- navegação local quando necessário;
- controles primários;
- filtros e busca quando aplicável;
- área principal de tarefa;
- feedback de estado;
- estados vazios e erros;
- ações persistentes quando forem críticas.

## Normalmente N/A

- hero comercial;
- pricing;
- prova social;
- CTA de venda;
- footer institucional completo;
- navegação comercial.

## Componentes Frequentes

- Button;
- Card;
- Input;
- Select;
- Combobox;
- Table;
- Tabs;
- Progress;
- Empty State;
- Tooltip;
- Alert;
- Toast;
- Pagination;
- Search;
- Filter Bar.

## Riscos Comuns

- usar layout de landing page para tarefa operacional;
- esconder controles essenciais abaixo de conteúdo editorial;
- usar PT Serif em tabelas ou controles;
- não tratar loading, erro e estado vazio;
- quebrar mobile por tabela sem overflow ou adaptação.
